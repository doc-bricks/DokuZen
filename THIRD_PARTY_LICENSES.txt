DokuZen - Third-Party License Inventory
===========================================

Status: direct runtime & tooling dependency inventory
Checked: 2026-08-24 (initial audit); Re-verified: 2026-10-01 (Pfad B Discoverability & Level 1 SBOM Audit; Prior: 2026-09-29) via PyPI JSON metadata and OSV / GHSA vulnerability audit for direct packages in `requirements.txt` and `requirements-dev.txt`.

Scope
-----

This file lists DokuZen's direct Python runtime dependencies from
`requirements.txt` as well as development and packaging tooling from
`requirements-dev.txt`. It is intentionally not a frozen transitive SBOM and does
not claim to enumerate every wheel pulled by pip at install time.

DokuZen itself is licensed under AGPL-3.0-or-later. Because the runtime stack includes
AGPL/GPL components, a Microsoft Store or binary release must keep source-code
availability, notices, and corresponding-license obligations aligned. A
proprietary binary release would require separate commercial licensing for the
copyleft components where available, especially PyMuPDF/Artifex.

Release Checklist Impact
------------------------

- Keep this inventory synchronized when `requirements.txt` changes.
- Before a public binary or Store release, generate a real frozen SBOM from the
  exact build environment and compare it with this direct inventory.
- Do not mark a proprietary release path ready while PyMuPDF is used under AGPL
  without a commercial Artifex license.
